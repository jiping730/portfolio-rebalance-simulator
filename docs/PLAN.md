# 开工方案：投资组合分析与调仓模拟

> 版本：v0.1（开发前原始方案）｜目标：3–4 小时完成可运行原型，优先验证核心业务规则与端到端流程。

## 1. 需求与边界

实现单用户、单组合、单币种 CNY、固定行情快照的原型：组合概览、单一标的/行业集中度检查、多笔买卖模拟、方案保存与重开。现金计入总资产分母但不计入行业；严格大于 30%/50% 才提醒；有效模拟前后总资产等于原始总资产（本示例为 100,000 元）。

必须支持后端计算与校验、前端错误反馈、原始组合和模拟组合隔离、刷新及重启后恢复方案。明确不做登录、多用户、实时行情、外部 API、真实下单、手续费税费、分红、融资、卖空、收益预测、风险评分、投资建议，以及方案编辑删除。价格缺失、价格非法或行业为空的处理策略写入设计文档，本次不做数据修复。

## 2. 最小范围与技术选择

- 前端：React + TypeScript + Vite；后端：Node.js + Express + TypeScript。
- 存储：本地 JSON 文件；测试：Vitest。
- 后端作为唯一计算口径；金额统一转换为整数分；比例告警使用整数交叉相乘，不使用展示舍入值。
- 保存 `snapshotId`、方案名、操作列表、创建时间，不保存现金、持仓、集中度等派生结果；重开时从原始快照重新执行并计算。
- 调仓请求采用整批原子性：任意一笔失败，丢弃本次全部临时状态，不产生部分结果，也不可保存；前端保留上一次成功结果。
- 优先级：后端计算与校验 → 概览和集中度 → 调仓对比 → 持久化 → 页面美化。

## 3. AI 协作方式

先以任务书、示例 JSON、AC-01～AC-05 建立类型、规则和接口契约，再分模块生成计算函数/API、页面和测试。每块生成后立即运行测试或人工复算；不接受需求外功能。记录实际使用的 AI 工具、关键提示、生成结果、人工修改及采用依据，开发完成后写入 DESIGN.md。

## 4. 验证计划

- AC-01：初始总资产 100,000；A01 40%提醒；科技 60%提醒。
- AC-02：卖出 A01 100 后现金 30,000；A01 30%、科技 50%，均不提醒。
- AC-03：接 AC-02 买入 A02 100 后现金 25,000；A02 数量 500；科技 55%提醒。
- AC-04：买入 201、卖出 401、零、负数、小数均拒绝，结果不改变。
- AC-05：保存 AC-03，刷新/重启后重开结果一致，原始现金 20,000、A01 400、A02 400。

另测整批回滚、总资产守恒、现金不计入行业、空方案名、空操作列表、非法 JSON、未知方案和快照异常。

## 5. 风险与待确认问题

主要风险是金额精度、阈值边界、模拟状态污染和文档与实现不一致。任务书与示例数据已足以开工，无额外待确认问题；实际耗时、未完成项、已知问题和与本方案的差异在开发完成后如实补充。
